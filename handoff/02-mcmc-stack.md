## 1. Why this exists

XModFit's MCMC exists to put honest error bars and correlation structure on X-ray-reflectivity fits, most importantly on `XLayersPDB`-family models where a rigid protein's orientation (theta, phi), insertion depth and coverage are strongly correlated and the posterior is genuinely multimodal — a least-squares stderr is meaningless there. Three things had to change for that to be practical. (a) Speed: an `XLayersPDB` `y()` evaluation costs ~1.6–3 ms, so a 10k-step 20-walker chain is tens of minutes serial; the objective had to be made picklable so emcee could use a process pool. (b) Correctness of the chain: theta/phi live on a sphere, so the walkers must be wrapped into the fundamental domain `[0,180] x [0,360)` each step and the autocorrelation of an angle must be computed circularly, or phi random-walks to +/-thousands and tau is nonsense. (c) Usability over long runs: chains run for 10^5+ steps, so they must live in an `.h5` file that can be closed, reopened and appended to, with a guard against continuing a chain into the wrong dataset. On top of that the joint-fit engine (multi-dataset shared-parameter fitting) needed the same MCMC treatment, which meant a second MCMC window and a second picklable objective spanning several models.

## 3. How it works

### 3.1 Dispatch inside `Minimizer.emcee`

`Minimizer.emcee` (`lmfit/minimizer.py:1534`) gained three new kwargs (`seed_temperature`, `seed_uniform_frac`, `walkers_per_basin`, lines 1538-1539) and four decision points:

1. **`orient_seed`** (`:1825`) = `funcname in _PDB_FUNCNAMES` **or** `getattr(self, '_orient_seed', False)`. The `or` is what generalises the PDB special-casing to a joint fit whose shared master params include theta/phi — `JointFit.set_emcee_minimizer` sets the attribute (`Joint_Fit_Routines.py:926`, `:981`). `_PDB_FUNCNAMES` (`:94-95`) replaced upstream's scattered `funcname == 'XLayersPDB'` string tests with one tuple of six names.
2. **Sampler class** (`:2208-2221`): `orient_seed` -> `lmfit.customsampler.CustomSampler`, else stock `emcee.EnsembleSampler`. Only `CustomSampler` wraps angles.
3. **Objective** — three possibilities, in order:
   - default `self._lnprob` (bound method on the `Minimizer`, which closes over `self.userfcn` = `Fit.residual` / `JointFit.residual`, both bound to a `QObject`);
   - `pdb_logprob.PdbLogProb` when `funcname in _PDB_FUNCNAMES and workers > 1` (`:2102-2150`);
   - `self._ext_objective` when it is set, `not pdb_names`, and `workers > 1` (`:2152-2191`).
4. **Run dispatch** (`:2245-2256`): `orient_seed` -> `sampler.custom_run_mcmc`; else if an external parallel objective is active -> a manual `for output in self.sampler.sample(...)` loop so the per-step hook runs in the main process; else stock `run_mcmc`.

### 3.2 Why the stock objective cannot be pickled, and what replaced it

`self._lnprob` calls `self.userfcn`, i.e. `Fit.residual`. `Fit` is a `QObject` holding a `pyqtSignal` (`Fit_Routines.py` class header) — unpicklable, and `dill` does not help. `multiprocessing.Pool.map` therefore raised `TypeError: cannot pickle 'Fit' object` at `cores > 1`. Note the stock lmfit code still creates a pool unconditionally at `:1789-1796` when `workers > 1 and HAS_DILL`; the two new blocks `terminate()` that pool and replace it with a `get_context('spawn').Pool(workers, initializer=..., initargs=...)`.

`pdb_logprob.PdbLogProb` (`pdb_logprob.py:57`) is the replacement for a single model. Design points, each load-bearing:
- The **model is shipped once** via the Pool `initializer` (`init_worker`, `pdb_logprob.py:47`) into a per-process `_W` dict, not per call — a `XLayersPDB` pickles at ~25 KB but shipping it per step would dominate.
- `__getstate__` (`:83-88`) *blanks* the embedded model/data so the callable itself pickles tiny; workers resolve from `_W` (`_resolve`, `:90-93`). The embedded-model form exists for serial/unit-test use.
- It reproduces `_lnprob`'s **vector-residual branch only**: `-0.5*sum(resid^2)`, the `__lnsigma` variant, out-of-bounds -> `-inf`, non-finite -> `-1e100` (`:95-116`), and `_scale_residual` (`:35-45`) mirrors `Fit.residual`'s four `fit_scale` cases. The claimed verification is 0.0 difference against the real `Fit.residual`.
- It sets both `setattr(model, name, val)` **and** `p[name].value` (`:102-104`) because the PDB models read `theta`/`phi`/`protins`/`cov` as plain attributes in `y()` but constraints live on the lmfit params.
- `_lnprob`'s `sin(theta)` prior is *not* applied. That prior only lives in the scalar-posterior branch (`minimizer.py:1514-1526`), which is dead for a vector XRR residual. That branch also previously contained `theta(angleind)` — a `NameError` waiting to happen; it now indexes theta out of the parameter vector.

`pdb_joint_logprob.JointLogProb` (`pdb_joint_logprob.py:62`) is the same idea across N models. It additionally reimplements `JointFit.push_params` (master value -> every `(obj_idx, local_key)` endpoint, clearing a dynamic `expr`, `:104-113`), the **per-curve max-normalisation** that `JointFit.residual` applies (`_scale_residual_norm`, `:33-46`), concatenation across datasets, and the optional Gaussian prior terms. Only the **plain (no-covariance)** branch is implemented; the whitened/GLS residual is deliberately absent (module docstring `:17-20`).

### 3.3 Progress and abort moved to a main-process per-step callback

Pool workers can neither emit `Fit.functionCalled` (a Qt signal) nor observe `fit_abort`. The stock design bumped `result.nfev` and called `iter_cb` inside `_lnprob`, i.e. inside the worker. So progress/abort was moved out of the objective and into a **per-step hook run in the parent**: `CustomSampler.step_callback`, invoked once per stored step at `lmfit/customsampler.py:294-295`. Two closures build it — `_step_cb` for the PDB path (`minimizer.py:2134-2147`) and `_ext_step` for the external path (`:2174-2187`). Each adds `nwalkers` to `result.nfev`, calls `iter_cb`, raises `AbortFitException` on abort (caught at `:2257`), and emits `functionCalled` inside a bare `try/except`. Routing at `:2218`: `step_callback = pdb_step_cb if pdb_step_cb is not None else ext_step_cb` — that single line is what made *parallel joint orientation-seeded* sampling work, because the pool and `JointLogProb` were already being installed by the `_ext_objective` block while the run went through `custom_run_mcmc` (which wraps angles in the parent, `customsampler.py:236-282`, and maps the log-prob through `self.pool.map`, `:205-211`).

Both parallel blocks are wrapped in `try/except` that falls back to `self._lnprob` with `pool = None` (`:2148-2150`, `:2188-2191`), so a failure to build the picklable objective degrades to serial rather than crashing.

### 3.4 The `.h5` backend, resume and the fingerprint guard

`CustomHDFBackend` (`lmfit/customhdf.py:41`) is emcee's `HDFBackend` re-parented onto `CustomBackend` so that `get_autocorr_time` is the angle-aware one. `reset` (`:105`) creates the `mcmc` group with resizable `chain`/`log_prob` datasets; `grow` (`:203`) resizes to `iteration + ngrow`; `save_step` (`:243`) writes at `iteration` and increments the attr. **That is the whole resume mechanism**: resuming grows and appends, it never rewinds, so autocorrelation and `np.corrcoef(flatchain)` after a resume span the whole run.

Which backend class is used is chosen in the GUI, not the engine: `xmodfit.py:3006-3009` (load) and `:3111-3114` (create) pick `CustomHDFBackend` when `self._mcmc_is_pdb()` else `emcee.backends.HDFBackend`.

Two resume bugs were fixed in `Minimizer.emcee`:
- A `backend.reset(...)` that would have **wiped a resumed chain** lived in a dead `elif (funcname in _PDB_FUNCNAMES) and reuse_sampler` branch shadowed by the earlier `if reuse_sampler`. The branch is gone; the comment at `:2086-2089` records why. Resets now happen only in the fresh-seed branch (`:2083-2084`) and the generic branch (`:2094-2095`), both guarded on `self.backend is not None`.
- Because the reuse branch never populated `moves`/`angleindex`, a **resumed** `XLayersPDB` run built a `CustomSampler` with no `angleindex` and stopped wrapping — phi random-walked off after the load/resume seam. Fixed by applying them with `setdefault` immediately before sampler construction, for both fresh and resumed runs (`:2200-2206`).
- `self.backend = backend` is now bound **unconditionally** (`:1808-1816`) because XModFit legitimately passes `backend=None` (cancelled dialog, or a declined fingerprint mismatch) and the attribute is read further down.
- The reuse branch's `self.sampler.pool = auto_pool` is guarded with `getattr(self, 'sampler', None) is not None` (`:1858`) — XModFit builds a fresh `Minimizer` per run, so `self.sampler` does not exist and this raised `AttributeError` on "load a sampler, sample more" at cores>1.

**FINGERPRINT guard** (`xmodfit.py:2871-2961`). Upstream only checked that every current parameter *name* appears in the `.h5` attrs (`minimizer.py:1733-1740`, preserved). That let a chain from a different dataset be loaded and continued. `_mcmc_fingerprint` (`:2871`) builds `{funcname, joint, varnames, dataset, ndata, datahash}` where `datahash` is a sha1 of the **active** y-values — deliberately the masked/active points rather than the `[imin,imax]` window, because a per-column limit changes which points are fitted without changing `imin/imax` (`:2883-2887`). `_write_mcmc_fingerprint` (`:2913`) stores it as the `xmf_fingerprint` attr at the end of `perform_post_sampling_tasks`, plus the tau trajectory as dataset `xmf_autocorr_time`. `openMCMCBackendFile` reads it, and on any difference (`_mcmc_fingerprint_mismatch`, `:2943`) shows a warn+confirm defaulting to **No**, setting `backend = None` on decline (`:3013-3026`). Files with no fingerprint get a soft info note and proceed (`:3027-3033`).

### 3.5 Autocorrelation

Three distinct tau computations, deliberately different:

- **Angle-aware integrated tau.** `customautocorr.function_1d` (`:20`) computes the ACF from `cos`/`sin` components when the parameter's `angleindex` is `3`, else the standard mean-subtracted FFT ACF. `integrated_time` (`:63`) takes `angleindex` as a **positional** argument and pads it with zeros to one entry per parameter (`:113-115`) — that padding is the `babe1aa` crash fix: lmfit's internal `get_autocorr_time()` passes no `angleindex`, `CustomBackend` defaults to `[]`, and the resulting `IndexError` escaped lmfit's `AutocorrError` guard. `CustomBackend.get_autocorr_time` (`custombackend.py:13`) is a plain `get_chain -> customautocorr.integrated_time`; the redundant `super().get_autocorr_time(discard=0, ...)` whose result was discarded (so every call autocorrelated the chain twice) has been removed, with the reasoning left in the comment at `:32-37`.
- **Live tau during sampling** (`xmodfit.py:3537-3565`). Full-chain (`discard=0`, `tol=0`) — the same quantity the load-time reconstruction produces, so the live points continue that curve with no cliff at the seam. Cadence is length-scaled, `_interval = max(100, step_now // 50)` gated on `self._last_autocorr_step` (`:3543-3546`), replacing upstream's `if MCMC_starting_step % 100 == 0`: frequent when N is small and cheap, sparse later, so each O(N log N) recompute stays a roughly constant slice of wall time. The autocorrelation tab is raised only on the first point (`:3563-3564`), not on every update.
- **tau-vs-step trajectory on load** (`_autocorr_trajectory`, `:2963-2990`). Computes `integrated_time` over ~40 increasing prefixes `chain[:n]`, angle-aware for PDB and stock `emcee.autocorr` otherwise. `openMCMCBackendFile` **prefers** the persisted `xmf_autocorr_time` dataset (an O(1) read) and only reconstructs for older files, falling back to a single recomputed point (`:3049-3065`).

**Per-parameter ACF-vs-lag is lazy.** `perform_post_sampling_tasks` no longer runs the FFT-per-walker-per-parameter loop; it sets `self._acf_dirty = True`, draws an "Open this tab to compute…" placeholder, records `self._sampled_keys`, and lands on tab 3 (autocorr *time*) rather than tab 2 (`:3680-3691`, `:3718-3720`). `_on_mcmc_tab_changed` (`:3572`) fires `_compute_parameter_acf` (`:3585`) the first time tab index 2 is opened. The ACF itself uses full-range `nlags = len-1` with an incremental per-walker mean (O(N) memory) and a thinned plot of <=3000 points (`:3607-3621`) — `sm.tsa.acf(fft=True)` costs the same regardless of `nlags`, so the earlier 2000-lag cap only truncated the curve without saving time.

### 3.6 Corner plot, CI table, pop-out

Upstream's `cornerPlot` was one monolith that always plotted every key of `param_chain`. It is now split (`xmodfit.py:3752-3846`): `_corner_names(subset)` (skips `__lnsigma`, optional subset filter), `_rebuild_pardata(first)`, `_corner_truths` (median fallback for params absent from `final_fit_params`), `_corner_render_data(cols)` (thins to `_CORNER_MAX_SAMPLES = 20000` rows for **rendering only**), and `_draw_corner(fig, ...)` which renders into any figure — the embedded widget, a subset re-plot, or a pop-out. `cornerPlot` caches the plotted names/cols/bins/percentile so `calcMCMCerrorbars` and the pop-out stay consistent with what was drawn. `calcMCMCerrorbars` (`:3849`) now uses those cached names and quantiles the **full** `pardata`, so reported statistics are unthinned; its `fig.axes.reshape((ndim,ndim))` is wrapped in `try/except ValueError` (`:3859-3862`) — upstream computed `ndim` from all of `param_chain` including `__lnsigma` while plotting one fewer, which made that reshape raise. `popOutCornerPlot` (`:3904`) re-renders the last-drawn subset into a non-modal `QDialog` + `MplWidget` with the matplotlib toolbar; the button is inserted into the corner tab of **both** windows by `_add_corner_popout_button` (`:3885`).

### 3.7 The two MCMC windows

`confInterval_emcee(joint=False)` (`:2691`) loads the same `UI_Forms/EMCEE_ConfInterval_Widget.ui` in both cases. For `joint=True` it additionally calls `_augment_joint_mcmc_tabs` (`:3947`), which appends two programmatic tabs: **Param Subset** (a checkable `jointSubsetList` with Select-all / Structural-only / Clear / Plot-subset, defaults checked by `_is_structural_param`, `:3934`) and **Summary** (`jointCorrMPLWidget` correlation heatmap + `jointCITable` median +/- CI, filled by `_update_joint_summary`, `:4033`). `self._mcmc_is_joint` is the authoritative flag; it is set here (`:2715`) and cleared on window Close in `eventFilter` (`:2626-2632`). If a window of the *other* kind is open it is closed and replaced rather than re-raised (`:2703-2712`). While a window is open, the main-window dataset/function/fit controls are disabled by `_lockMainSelectionForMCMC` (`:2603`) so `self.fit` cannot be swapped out from under the sampler.

Entry points: the individual window from `calcConfInterval` (`:2212`), which now **refuses** with a guide dialog when `jointFitEnabled` (`:2216-2226`); the joint window from the Joint Fit panel's always-enabled `jointMCMCBtn` (`joint_fit_panel.py:301-310`) -> `confInterval_joint_emcee` (`:2671`). `confInterval_joint_emcee` sets `self.fit = jointFit` and computes `errorAvailable = getattr(jf.result, 'flatchain', None) is not None` — **not** `hasattr`, because lmfit's `MinimizerResult.flatchain` is a property that returns `None` for a least-squares result, so `hasattr` is always True and drove the window-construction code into `None[var_names[0]]`. `_show_param_error` (`:2660`) is a no-arg router for the shared "Show Param Error" button (it also stops `QPushButton`'s `checked` bool landing in the `joint` kwarg).

**None-safe helpers.** While a joint fit is active the main `funcListWidget` has no current item, so the ~9 `funcListWidget.currentItem().text() in (...)` tests in the MCMC flow raised `NoneType.text()`. In `startMCMCBackendFile` that raised *before* `self.backend` was assigned, leaving it `None`, which surfaced to the user as "please create a new MCMC file" when they had just created one. Replaced by `_mcmc_funcname()` (`:2636`, joint -> `type(fit.objectives[0]['func']).__name__`, else current item or `''`) and `_mcmc_is_pdb()` (`:2655`, membership in class constant `_PDB_MCMC_FUNCS`, `:2634`). Call sites: `:2804, 3006, 3035, 3111, 3249, 3394, 3501, 3547, 3592, 3643`.

### 3.8 Control flow, joint MCMC

`Start Sampling` -> `start_emcee_sampling` (`:3325`) -> `doFit(fit_method='emcee', ...)`. `doFit` routes the joint case **first, before all individual-fit guards** (`:1731-1737`), because those guards (`sfnames == []`, `fit.fit_params`, a selected function) fire spuriously when the joint MCMC window is driving. A second route exists at `:1780-1789` for the case where a joint dataset is selected in the panel. `run_joint_emcee` (`:7149`) reuses the already-fitted `JointFit` at `self.fit` (it does **not** recompile or re-fit), rebuilds the per-dataset `ranges` so the MCMC window matches the least-squares fit exactly, connects `fitErrorCallback`, and calls `JointFit.perform_fit(..., fit_method='emcee', seed_temperature=, seed_mode=)`. `JointFit.perform_fit` (`Joint_Fit_Routines.py:1023-1038`) passes `workers = emcee_cores` only when `emcee_cores > 1 and not self._use_cov and fitter._ext_objective is not None`.

`JointFit._attach_joint_parallel` (`:855`) is the single place that builds `JointLogProb` and sets `fitter._ext_objective`, `fitter._ext_obj_init = (init_worker, (models, datas))`, `fitter._ext_workers`. It is gated on `emcee_cores > 1 and not self._use_cov` and is called from every branch of `set_emcee_minimizer` (`:930`, `:987`, `:1001`).

## 4. How to use it

**Individual MCMC.** Fit a dataset normally (least-squares) — this is no longer strictly required (see 6) but gives the best starting point. Set *Conf. Interval Method* = `MCMC`, click **Calculate Param Error**. In the window: **Start MCMC file** (creates a fresh `.h5`, default `./mcmc_chain.h5`) or **Load MCMC file** (resume an existing chain). Set Walkers / Steps / Burn / Thin / **Parallel cores**, and for an `XLayersPDB*` model the **Seed temperature (T)** spinbox (grid row 4, added programmatically at `xmodfit.py:2814-2832`; disabled with an explanatory tooltip for non-PDB functions). Click **Start sampling**. **Stop** aborts cleanly and still produces chains/corner/CI. Then **Calculate Confidence Interval** for the corner plot + CI table, and **Pop out** for a zoomable copy. Resuming: load the `.h5`, `Reuse sampler` is checked automatically, press Start again — the chain appends and the tau curve continues.

**Joint MCMC.** Run a joint least-squares fit in the Joint Fit panel, then click **Joint MCMC / Param Error…** in that panel (always enabled; it explains itself if no joint fit exists). Same file/sampling controls, plus **Seed from: Joint landscape / Individual landscapes** (grid row 5, enabled only for a both-shared joint fit) and the two extra tabs: **Param Subset** (structural/shared params checked by default — a joint fit has too many per-dataset params for a legible corner plot) then **Plot subset**, and **Summary** (median +/- CI table and correlation heatmap over the plotted subset).

**Which models get the Custom* path.** `CustomHDFBackend` + `angleindex` autocorrelation is chosen by `xmodfit._PDB_MCMC_FUNCS = ('XLayersPDB', 'XLayersPDB_box', 'XLayersPDB_dev_smooth')`. `CustomSampler` + orientation seeding + the parallel `PdbLogProb` is chosen by `minimizer._PDB_FUNCNAMES` (six names, adds `_G`, `_H`, `_XPR`). A joint fit with shared varying theta/phi also gets `CustomSampler` via `_orient_seed`. Everything else gets stock `EnsembleSampler` + `emcee.backends.HDFBackend`.

**Measured speedups (from the notes, not re-measured here).** Individual `XLayersPDB` sampling, i2_tim3 case, 32-core box, 8 workers, 20 walkers: 70.7 ms/step serial -> 13.8 ms/step parallel, ~5x; a 10k-step run ~13 min -> ~3 min. There is a one-time ~15–25 s cost for spawning the pool plus numba JIT warmup in each worker, so short test runs look *slower*; measure with a delta between two step counts. Parallel sampling does **not** apply to covariance/GLS joint fits (still serial), and a synthetic toy model will show parallel as slower because IPC dominates a trivial `y()`.

**Test interpreter:** `C:\Users\kerr\.conda\envs\cmc-py39\python.exe`, headless with `QT_QPA_PLATFORM=offscreen` and a stubbed `sys.modules['xraydb']`. Any headless test that triggers a spawn `Pool` **must** be under `if __name__ == '__main__':` or it re-imports itself and fork-bombs.

## 6. Known limitations, gotchas and TODOs

- **Covariance/GLS joint MCMC is serial.** `JointLogProb` has no whitened residual; `_attach_joint_parallel` is gated `not self._use_cov` and `run_joint_emcee` prints "runs serially, ignoring cores". Porting it needs a covariance dataset to validate bit-for-bit first.
- **Three inconsistent PDB name lists.** `minimizer._PDB_FUNCNAMES` (6 names) vs `xmodfit._PDB_MCMC_FUNCS` (3) vs the inline tuple in `Fit_Routines.set_emcee_minimizer` (3, a different 3). Consequence found by reading the code: for `XLayersPDB_XPR` / `_G` / `_H`, `Minimizer.emcee` builds a `CustomSampler` while the GUI hands it a stock `emcee.backends.HDFBackend`; `CustomSampler.get_autocorr_time` then calls `backend.get_autocorr_time(angleindex=...)`, which stock emcee forwards to `emcee.autocorr.integrated_time` — an unexpected keyword, i.e. `TypeError`, and `TypeError` is *not* in the `except` list at `minimizer.py:2300-2302`. See audit hook #1.
- **`_lnprob` is still unpicklable for non-PDB models at cores>1.** Stock lmfit creates a pool whenever `workers > 1 and HAS_DILL` (`minimizer.py:1791-1793`) and `dill` *is* installed in the test env. A non-PDB individual model with a joint-less `_ext_objective` unset will still get a pool with the Qt-bound objective. Pre-existing upstream behaviour; not fixed.
- **Two spawn Pools per PDB run** (one for the seeding scan, one for sampling) — the notes flag unifying them as deferred perf work, plus adding numba JIT warmup per worker under the "Initializing…" label.
- **`CustomSampler.get_autocorr_time` still double-computes.** `super().get_autocorr_time(**kwargs)` at `customsampler.py:336` discards its result — the exact pattern that was removed from `CustomBackend`. It also means the *default* `tol=50` path can raise before the real (angle-aware) value is returned; that raise is what `_AUTOCORR_ERRORS` catches.
- **Two `AutocorrError` classes.** `emcee.autocorr.AutocorrError` and `lmfit.customautocorr.AutocorrError`. `EnsembleSampler.get_autocorr_time` delegates to the backend, so with a `Custom*Backend` the raised class is ours. Anything catching only emcee's will leak — this is exactly what made "nothing shows after Stop" happen, since a manually-stopped chain is always shorter than 50*tau.
- **Resume ETA.** Upstream computed `time_left = time_taken * (emcee_steps - MCMC_starting_step)`, which goes negative on a resume where the loaded chain is longer than the requested step count; `time.gmtime(negative)` raises `OSError [Errno 22]` on Windows, killing the per-step callback and stalling the run at "Initializing". Now derived from this session's rate (`_mcmc_session_start_step`), clamped finite/non-negative and capped to 359999 s (`xmodfit.py:3516-3530`).
- **`backend.reset` when the backend is None.** All three reset sites are guarded (`minimizer.py:2083`, `:2094`), because a cancelled "Start MCMC file as" dialog leaves `backend=None`.
- **A rising full-chain tau that never plateaus is not a bug** — it is the classic not-yet-converged signature (`N/tau < 50`).
- **`_ext_workers` is written and never read** (`Joint_Fit_Routines.py:884`); `Minimizer.emcee` uses the `workers` argument only.
- **Stale docstring:** `JointFit.set_emcee_minimizer`'s docstring still says the orientation-seeded joint path "is SERIAL" (`Joint_Fit_Routines.py:900`) — that was flipped when parallel joint sampling landed. `perform_fit` and `run_joint_emcee` were updated; this one was missed.
- **Corner-plot pop-out zoom** is per-axes only (matplotlib rubber-band); the user asked for whole-grid zoom — deferred.
- **Not done** in the corner work: per-parameter trace plots, group-by-dataset.
- **`XLayersPDB_dev_smooth` does not mix better than `XLayersPDB`** despite being erf-smoothed (tau ~384 vs ~238, acceptance 0.075 vs 0.139, ~3x slower per eval on i2_tim3). The smoothness rework helps derivative-based fits, not MCMC mixing. Single stochastic run, tau in the untrustworthy regime — treat as indicative.
- **Never validate against emcee's stock `HDFBackend`** in a headless test. Doing so masked the double-`AutocorrError` bug for weeks; the GUI backend for `XLayersPDB`/joint is `CustomHDFBackend`.

## 8. Consolidation candidates

- **The three PDB-name lists** (`minimizer._PDB_FUNCNAMES:94`, `xmodfit._PDB_MCMC_FUNCS:2634`, the inline tuple at `Fit_Routines.py:491`). Recommendation: **merge** into one module-level tuple imported by all three (`lmfit.minimizer._PDB_FUNCNAMES` is the natural home, or better a small `pdb_models.py` so the GUI need not import from vendored lmfit). Risk: low; but the merged list changes behaviour for `_box`/`_G`/`_H`/`_XPR` (they would start getting `CustomHDFBackend` and `fiterr`), so it needs one MCMC run per newly-included model to confirm nothing regresses.
- **`CustomSampler.get_autocorr_time`'s discarded `super()` call** (`customsampler.py:336`). Recommendation: **drop** the `super()` line, matching what was already done in `CustomBackend`. Risk: low-moderate — the `super()` call is currently the thing that raises `AutocorrError` on a short chain (the backend call passes `tol` through too, so the raise should be preserved, but this must be checked before removing).
- **`pdb_logprob.py` and `pdb_joint_logprob.py`** duplicate `_scale_residual` / `__getstate__` / `_resolve` / the `__lnsigma` reduction, differing mainly in max-normalisation and the `push_params` fan-out. Recommendation: **keep separate for now** (they are validated bit-for-bit against two *different* residual implementations, and a shared base class risks silently changing one). Revisit only if a third objective appears — e.g. the covariance/GLS joint objective, which is the obvious next one.
- **`_ext_workers`** (`Joint_Fit_Routines.py:884`): dead. Recommendation: **drop**. Risk: none.
- **`EMCEE_Widget.py`** (780 lines, upstream's parallel non-lmfit MCMC) is imported by nothing in this tree, while `Fit.log_likelihood`/`log_prior`/`log_probability` exist solely to serve it. Recommendation: **decide with upstream** rather than unilaterally — either wire it up as a second MCMC front-end or remove it plus its three `Fit` methods. Risk of removing: high politically (it is upstream's own new feature and the merge is about to go back), so leave it alone and flag it.
- **The angleindex-construction loop** (`for var_name in var_names: 1 if 'theta' else 2 if 'phi' else 0`) is copy-pasted five times in `xmodfit.py` (`:3036-3045`, `:3395-3404`, `:3502-3511`, `:3593-3595`, `:3644-3653`) and once more in `minimizer.py:1833-1844`. Recommendation: **merge** into one `XModFit._mcmc_angleindex()` helper. Risk: low, but note the joint per-dataset case deliberately does *not* use the bare-name test (per-dataset angles are `d{i}_theta`) — the helper must keep honouring `fitter._angleindex`.
- **`self.autoCorrTime` appending** happens in four places (`runFit:3413`, `fitErrorCallback:3552`, `perform_post_sampling_tasks:3662`, and `openMCMCBackendFile` which *replaces* it). Combined with `MCMC_starting_step = autoCorrTime[-1,0]`, the array doubles as both the plotted curve and the resume bookkeeping. Recommendation: **keep but document** — separating them is a real refactor and the fingerprint persistence now depends on the current shape.
